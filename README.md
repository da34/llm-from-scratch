# LLM from Scratch

## 项目简介

根据纳米 AI 的课程进行学习。

## 课程内容

### [lesson-01](lesson-01/)：Agent 循环

- **解决的问题**：从一问一答的聊天助手到真正能干活的 Agent。
- **核心机制**：在主循环里调用模型和工具，直到模型不再请求调用工具。
- **为什么这样设计**：是否调用工具就是本轮继续还是结束的信号。

### [lesson-02](lesson-02/)：工具调用

- **解决的问题**：从能干活到能稳定干活，需要对 Agent 的工具调用加上权限控制。
- **核心机制**：放行白名单工具，像 `bash` 这样的工具每次调用都需要人工确认，危险命令直接拒绝。
- **为什么这样设计**：模型有时会犯错，需要由 harness 控制工具执行，避免不可逆的后果。

### [lesson-03](lesson-03/)：工具封装与权限

- **解决的问题**：工具调用不受控时，LLM 的操作可能导致系统崩溃。
- **核心机制**：封装 `tool`，新增工具不需要改主循环，并将工作区限制在启动目录。工具调用按权限处理：
  - 白名单内的读操作等无副作用操作直接放行。
  - 需要审批的命令交由人工确认。
  - 匹配拒绝规则的危险命令直接拦截，比如高危的 `rm` 命令。
- **为什么这样设计**：约束工具调用，让 LLM 的运行过程更可控，避免副作用。

#### 流式输出

只改展示层，不需要改动主循环逻辑：

1. 用客户端的 `stream` 方法发起请求。
2. 收到 `content.delta` 事件时，直接打印新增内容。
3. 不在逐条处理事件时添加消息。等输出结束后，再用 `get_final_completion()` 获取完整消息并添加到 `messages`。

### [lesson-04](lesson-04/)：上下文管理

- **解决的问题**：循环中 `messages` 会持续增长，但 LLM 的上下文窗口有限，且大小因模型而异。
- **核心机制**：按成本从低到高分三层处理：
  1. 工具结果入库前截断。
  2. 清理旧的工具结果。
  3. 用 LLM 对早期对话进行摘要。
- **为什么这样设计**：处理成本逐层递增，所以优先用成本低的办法。

### [lesson-05](lesson-05/)：按需加载 Skill

- **解决的问题**：把个人或团队的规范都写进系统提示词，会在不相关的任务中占用 token，比如不需要执行 `git commit` 时仍附带提交规范。
- **核心机制**：只把 Skill 的 `frontmatter` 中的 `name` 和 `description` 放进系统提示词，需要时再由 Agent 通过 `load_skill` 加载完整提示词。
- **为什么这样设计**：减少 token 开销，让模型专注于当前任务。

### [lesson-06](lesson-06/)：聊天渠道接入

- **解决的问题**：不用守在电脑前，也能指挥 Agent 干活。
- **核心机制**：抽象出 `channel`，可以接入 Telegram、飞书等聊天软件。
- **为什么这样设计**：利用现有的聊天软件，新增渠道时只需实现对应的 `channel` 方法，不必修改主循环。

## 环境准备

Python 3.x

## 运行方式

1. 在项目根目录创建虚拟环境：

   ```shell
   python -m venv .venv
   ```

2. 安装项目依赖：

   ```shell
   python -m pip install -r requirements.txt
   ```

3. 进入对应的课程目录，启动 `agent.py`：

   ```shell
   python agent.py
   ```
